# Worldbuilding Data Model
## Saga Architect - Lore Foundation Architecture

**Package ID:** com.bobbysworld.sagaarchitect
**Document Version:** 1.0 (MVP)

---

## Overview

Saga Architect uses a **7-entity relational data model** to represent fictional universes. Each entity type serves a specific purpose in worldbuilding while maintaining connections to create a cohesive canon.

The model prioritizes:
- **Canon tracking** - Every entity has a canon status
- **Relationship integrity** - Entities reference each other via IDs
- **Extensibility** - Optional fields allow rich detail without complexity
- **AI compatibility** - Structured fields enable AI generation

---

## Core Entities

### 1. Universe

**Purpose:** The top-level container for all lore in a fictional world.

**Fields:**

```typescript
interface Universe {
  // Identity
  id: string;                    // Unique identifier
  user_id?: string;              // Owner (for multi-user support)

  // Basic Info
  name: string;                  // Universe name
  concept: string;               // One-sentence concept

  // World Parameters
  genre: string;                 // fantasy, sci-fi, horror, etc.
  tone: string;                  // dark, hopeful, comedic, etc.
  era: string;                   // medieval, futuristic, modern, etc.
  tech_level: string;            // bronze age, industrial, cyberpunk, etc.
  magic_system: string;          // hard magic, soft magic, none, etc.

  // Core Lore
  world_overview: string;        // World description (AI-generated or manual)
  creation_myth: string;         // Origin story of the universe
  themes: string[];              // Major themes (sacrifice, revenge, etc.)
  current_conflict: string;      // Main ongoing conflict
  prophecy_hooks: string[];      // Unresolved prophecies/mysteries

  // Metadata
  created_at: string;            // ISO timestamp
  updated_at: string;            // ISO timestamp
}
```

**Relationships:**
- Has many: Characters, Factions, Locations, TimelineEvents, StoryArcs, LoreRules

**Canon Status:** Universes themselves don't have canon status (they are the canon container).

**Usage:**
- Created via Universe Forge
- Displayed on Dashboard
- Serves as context for all AI generation

### 2. Character

**Purpose:** Individual beings within the universe (protagonists, antagonists, NPCs).

**Fields:**

```typescript
interface Character {
  // Identity
  id: string;
  universe_id: string;           // Parent universe
  faction_id?: string;           // Optional faction membership

  // Basic Info
  name: string;
  title: string;                 // "The Last Oracle", "King of Ash", etc.
  role: string;                  // protagonist, antagonist, mentor, etc.

  // Personality & Motivation
  motivations: string;           // What drives them
  fears: string;                 // What they fear

  // Abilities
  powers: string;                // Supernatural/special abilities
  weaknesses: string;            // Vulnerabilities

  // Narrative
  arc_potential: string;         // Suggested character arc
  relationships: Relationship[]; // Connections to other characters

  // Status
  status: CharacterStatus;       // alive, dead, missing, legendary, unknown
  canon_status: CanonStatus;     // canon, draft, alternate, deprecated, mystery

  // Extended (Optional)
  appearance?: string;           // Physical description
  speech_style?: string;         // How they speak
}
```

**Relationships:**
- Belongs to: Universe
- Belongs to (optional): Faction
- Has many: Relationships (to other Characters)
- Referenced by: TimelineEvents, StoryArcs

**Canon Status Values:**
- `canon` - Official character in the universe
- `draft` - Character in development
- `alternate` - Alternate timeline version
- `deprecated` - Removed from canon
- `mystery` - Status unknown/hidden

**Character Status Values:**
- `alive` - Currently living
- `dead` - Confirmed deceased
- `missing` - Whereabouts unknown
- `legendary` - Mythical/historical figure
- `unknown` - Status unclear

**Usage:**
- Created via Character Engine
- Generated by AI with arc potential
- Linked in timeline events and story arcs

### 3. Faction

**Purpose:** Organizations, kingdoms, guilds, armies, cults, or groups.

**Fields:**

```typescript
interface Faction {
  // Identity
  id: string;
  universe_id: string;

  // Basic Info
  name: string;
  type: string;                  // kingdom, guild, cult, empire, etc.

  // Core Attributes
  ideology: string;              // Belief system/philosophy
  leader: string;                // Current leader
  resources: string;             // Wealth, military, magic, etc.
  territory: string;             // Controlled regions

  // Relations
  allies: string[];              // Allied faction names
  enemies: string[];             // Enemy faction names

  // Internal
  internal_conflict: string;     // Internal struggles
  objective: string;             // Primary goal

  // Visual
  symbol?: string;               // Faction emblem/sigil

  // Status
  canon_status: CanonStatus;
}
```

**Relationships:**
- Belongs to: Universe
- Has many: Characters (members)
- Has many: Allies (other Factions)
- Has many: Enemies (other Factions)
- Referenced by: TimelineEvents, StoryArcs

**Canon Status:** Standard 5-tier system.

**Conflict Detection:**
- Asymmetric ally/enemy relationships (A allies with B, but B enemies with A)
- Dead faction leaders (leader is a dead character)

**Usage:**
- Created via Faction Builder
- AI-generated with relationship networks
- Power dynamics tracked via allies/enemies

### 4. Location

**Purpose:** Physical places in the universe (cities, ruins, landmarks, realms).

**Fields:**

```typescript
interface Location {
  // Identity
  id: string;
  universe_id: string;

  // Basic Info
  name: string;
  type: string;                  // city, ruin, temple, forest, etc.
  region: string;                // Geographic area
  description: string;           // Visual/narrative description

  // Importance
  strategic_value: string;       // Military/economic value
  mythic_importance: string;     // Legendary/religious significance

  // Status
  canon_status: CanonStatus;
}
```

**Relationships:**
- Belongs to: Universe
- Referenced by: TimelineEvents, StoryArcs

**Canon Status:** Standard 5-tier system.

**Usage:**
- Created via Canon Core (locations section)
- AI-generated with strategic/mythic context
- Setting for timeline events

### 5. TimelineEvent

**Purpose:** Historical or current events that shape the universe's timeline.

**Fields:**

```typescript
interface TimelineEvent {
  // Identity
  id: string;
  universe_id: string;

  // Event Info
  title: string;                 // Event name
  era_marker: string;            // "Year 342", "The Fall", etc.
  summary: string;               // What happened

  // Impact
  affected_characters: string[]; // Character IDs involved
  affected_factions: string[];   // Faction IDs involved
  affected_locations: string[];  // Location IDs involved
  consequences: string;          // Long-term effects

  // Mystery Layer
  hidden_truths?: string;        // Secret information

  // Status
  canon_status: CanonStatus;
}
```

**Relationships:**
- Belongs to: Universe
- References: Characters, Factions, Locations

**Canon Status:** Standard 5-tier system.

**Conflict Detection:**
- Dead characters appearing in multiple events
- Chronological inconsistencies (planned)

**Usage:**
- Created via Timeline Engine
- AI-generated in chronological order
- Foundation for story arcs

---

### 6. StoryArc

**Purpose:** Narrative arcs spanning multiple events/characters/factions.

**Fields:**

```typescript
interface StoryArc {
  // Identity
  id: string;
  universe_id: string;

  // Arc Info
  title: string;
  type: ArcType;                 // trilogy, season, hero, villain, etc.
  summary: string;               // Arc overview

  // Structure
  start_point: string;           // Beginning
  end_point: string;             // Ending
  turning_points?: string[];     // Key moments

  // Involvement
  involved_characters: string[]; // Character IDs
  involved_factions: string[];   // Faction IDs
  themes: string[];              // Narrative themes

  // Status
  canon_status?: CanonStatus;
}
```

**Arc Types:**
- `trilogy` - Multi-book/game arc
- `season` - Series/season arc
- `hero` - Hero's journey
- `villain` - Villain's rise/fall
- `redemption` - Redemption arc
- `war` - Conflict arc
- `prophecy` - Prophecy fulfillment
- `empire_fall` - Civilization collapse

**Relationships:**
- Belongs to: Universe
- References: Characters, Factions

**Canon Status:** Standard 5-tier system.

**Usage:**
- Created via Arc Forge
- AI-generated from existing canon
- Templates for story generation

---

### 7. LoreRule

**Purpose:** Canon rules, constraints, and world laws.

**Fields:**

```typescript
interface LoreRule {
  // Identity
  id: string;
  universe_id: string;

  // Rule Info
  category: string;              // magic, physics, divine, social, etc.
  title: string;                 // Rule name
  description: string;           // Rule details

  // Scope
  applies_to: string[];          // Entities affected (all, characters, etc.)

  // Status
  canon_status: CanonStatus;
}
```

**Relationships:**
- Belongs to: Universe

**Canon Status:** Standard 5-tier system.

**Conflict Detection:**
- Duplicate rule titles
- Mystery rules with no resolution
- Deprecated rules in archive

**Categories:**
- `magic` - Magic system rules
- `physics` - Natural laws
- `divine` - Religious/pantheon rules
- `social` - Cultural norms
- `historical` - Historical facts
- `biological` - Species/creature rules

**Usage:**
- Created via Lore Memory
- AI-generated from universe parameters
- Consistency checking against new content

## Canon Status System

**Purpose:** Track the canon validity of every entity.

```typescript
type CanonStatus =
  | 'canon'      // Official, active lore
  | 'draft'      // In progress
  | 'alternate'  // Alternate timeline
  | 'deprecated' // Retired
  | 'mystery';   // Intentionally unknown
```

**Visual Representation:**
- `canon` - Green badge
- `draft` - Yellow badge
- `alternate` - Blue badge
- `deprecated` - Gray badge
- `mystery` - Purple badge

```typescript
interface LorePoolMeta {

```

**All entities extend LorePoolMeta** for optional sharing support.

## Data Flow

### Creation Flow
1. User creates **Universe**
2. User adds **Characters**, **Factions**, **Locations**
3. User creates **TimelineEvents** referencing entities
4. User generates **StoryArcs** from existing canon
5. User defines **LoreRules** for consistency

### AI Generation Flow
1. User provides **Universe** context
2. AI generates entities using **canon block** (all universe data)
3. New entities automatically reference existing canon
4. Canon status starts as `draft`
5. User reviews and promotes to `canon`

### Export Flow
1. LoreEngine builds **canon block** (all entities serialized)
2. Canon block formatted as JSON
3. External tools (Rainstorms) consume via API
4. Stories/books generated maintain canon consistency

## Conflict Detection

Saga Architect detects canon conflicts:

1. **Duplicate lore rule titles** (same category)
2. **Mystery rules** without resolution
3. **Deprecated rules** still marked as canon
4. **Dead characters** in multiple timeline events
5. **Asymmetric faction relationships** (A allies B, B enemies A)
6. **Magic rule violations** (planned)

---

## Design Principles

1. **Simple but Extensible** - Core fields required, optional fields for depth
2. **Relationship-First** - Entities reference each other via IDs
3. **Canon-Aware** - Every entity tracks its canon status
4. **AI-Friendly** - Structured data enables generation
5. **Cross-App Compatible** - Canon block exports to other tools
