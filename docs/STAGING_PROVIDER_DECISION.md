# Staging Provider Decision

Phoenix Creator Studio will use one staging architecture for the first production-like validation lane:

- **Application:** Vercel
- **Database:** Supabase PostgreSQL
- **Asset storage:** private Supabase Storage bucket
- **Distributed rate limiting:** Upstash Redis

This avoids scattering deployment configuration across multiple platforms before one path is proven.

## Runtime connections

- application queries use the Supabase serverless-compatible transaction pooler
- schema migrations use a separate migration-safe direct connection
- migrations run once as a deployment job, never from request handlers or readiness probes

## Storage policy

- local storage remains available only for development and isolated tests
- staging and production require durable private object storage
- object keys are generated by the application rather than trusted from user filenames

## Rate-limit policy

- in-memory limiting remains available only for development and isolated tests
- staging and production require a shared atomic backend
- readiness fails when the configured shared backend cannot be reached

## Promotion rule

No production environment will be created from this architecture until the staging acceptance and recovery exercises pass on an exact commit SHA.
